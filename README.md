# SOra2

SOra2 - Node.js/TypeScript сервис для генерации и постобработки коротких видео по Instagram Reels-референсам. В проект входят веб-админка, Telegram-бот, очередь генераций, хранение файлов в S3/Яндекс Диске и PostgreSQL-хранилище проектов.

## Возможности

- создание проектов под отдельные Telegram-темы;
- загрузка фото товара и синхронизация референсов с Яндекс Диском;
- прием ссылок на Instagram Reels через Telegram;
- анализ референсов, извлечение аудио и подготовка промптов;
- ручная генерация из веб-интерфейса;
- автоматическая генерация по дневному лимиту;
- ремиксы готовых генераций;
- финальная постобработка видео с текстовыми оверлеями и CTA;
- история генераций, статусы задач и ссылки на результаты.

## Быстрый старт

Требования:

- Node.js 22 или новее;
- PostgreSQL;
- `ffmpeg` и `ffprobe`;
- Chromium, если используется постобработка через браузерные инструменты;
- токены внешних сервисов из `.env.example`.

```bash
cp .env.example .env
npm install
npm start
```

По умолчанию веб-интерфейс будет доступен на `http://localhost:3000`.

Проверка здоровья:

```bash
curl http://localhost:3000/api/health
```

Ожидаемый ответ:

```json
{ "ok": true }
```

## Основные команды

```bash
npm start
npm run dev
npm test
```

`npm start` запускает приложение через `tsx src/index.ts`.

`npm run dev` запускает сервер через `nodemon` и перезапускает его при изменении TypeScript-файлов.

`npm test` сейчас является заглушкой и завершится ошибкой.

## Основные переменные окружения

Минимально нужны:

- `DATABASE_URL` - строка подключения к PostgreSQL;
- `TELEGRAM_BOT_TOKEN` - токен Telegram-бота, если бот должен работать;
- `WEB_PUBLIC_URL` - публичный URL веб-интерфейса для ссылок в Telegram;
- `OPENROUTER_API_KEY` - доступ к Gemini-моделям через OpenRouter;
- `KIE_AI_API_KEY`, `COMET_API_KEY`, `DEFAPI_API_KEY` - провайдеры генерации видео;
- `YANDEX_TOKEN` - загрузка итогов и референсов на Яндекс Диск;
- `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` - S3-совместимое хранилище;
- `RAPIDAPI_KEY` - получение данных по Instagram/Reels.

Полный список см. в `.env.example` и в разделе "Переменные окружения" подробной инструкции.

## Telegram-бот

Основные команды:

- `/start` - краткая справка;
- `/create_project <название> [topic-id]` - создать проект и привязать его к теме;
- `/bind_project <project-id> [название темы]` - привязать существующий проект к текущей теме;
- `/bind_topic <project-id> <topic-id> [название темы]` - привязать проект к конкретной теме;
- `/project_status` - показать текущую привязку;
- `/settings` - получить ссылку на веб-интерфейс проекта.

После привязки проекта отправляйте ссылки на Instagram Reels в ту же Telegram-тему. Бот добавит ролики в библиотеку референсов проекта.

## Деплой в Coolify

1. Запушьте проект в GitHub.
2. В Coolify создайте `New Resource -> Application`.
3. Выберите репозиторий и ветку.
4. Тип сборки: `Dockerfile`.
5. Порт приложения: `3000`.
6. Health Check Path: `/api/health`.
7. Создайте PostgreSQL и передайте `DATABASE_URL` в переменные приложения.
8. Добавьте остальные переменные из `.env.example`.
9. Добавьте постоянный volume:
   - `Source`: managed volume, например `sora2-data`;
   - `Target`: `/app/data`.
10. Нажмите `Deploy`.

Для продакшена рекомендуется Telegram webhook-режим:

```env
TELEGRAM_USE_WEBHOOK=true
TELEGRAM_WEBHOOK_URL=https://your-domain.com/telegram/webhook/sora2
TELEGRAM_WEBHOOK_PATH=/telegram/webhook/sora2
TELEGRAM_WEBHOOK_SECRET=long_random_secret
```

Если включен polling-режим (`TELEGRAM_USE_WEBHOOK=false`), запускайте только одну реплику приложения.

## Хранение данных

- PostgreSQL хранит проекты, привязки Telegram-тем, библиотеку референсов, задачи генерации и системные настройки.
- `/app/data` хранит загруженные изображения, временные файлы, аудио и кеши. В Docker/Coolify для него нужен постоянный volume.
- S3 хранит оригиналы и промежуточные артефакты.
- Яндекс Диск хранит пользовательские финальные файлы и синхронизированные референсы.
